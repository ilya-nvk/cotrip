# ТЕКСТ ПРОГРАММЫ

## 1. Клиентская часть
Клиентская часть CoTrip реализована в каталоге `android/app/src/main/java/nvk/cotrip`.

### 1.1 Структура клиентской части
1. `ui` - экраны и пользовательские сценарии (авторизация, поездки, идеи, маршрут, расходы, настройки, погода, AI-подсказки).
2. `data/repository` - прикладная логика сценариев и координация источников данных.
3. `data/network` - API-клиенты, перехватчики, сетевые модели.
4. `data/cache` - локальные кэш-хранилища клиентских сущностей.
5. `data/sync` - офлайн-очередь и синхронизация после восстановления сети.
6. `notifications` - обработка push-уведомлений и переходов по событиям.
7. `di` - конфигурация внедрения зависимостей.

### 1.2 Используемые библиотеки и назначение
1. Kotlin - основной язык клиентской реализации.
2. Jetpack Compose - декларативный UI клиентских экранов.
3. AndroidX Navigation - навигация между экранами.
4. Hilt / Dagger - внедрение зависимостей.
5. Retrofit + OkHttp + Kotlinx Serialization - HTTP-клиент и сериализация API-контрактов.
6. Room - локальная БД на клиенте.
7. WorkManager - фоновые задания синхронизации.
8. Firebase Cloud Messaging SDK - доставка push-уведомлений на устройство.

### 1.3 Обоснование выбора инструментов
1. Kotlin выбран для сокращения количества языков в проекте и упрощения сопровождения.
2. Compose выбран для управления состоянием UI и ускорения разработки экранов.
3. WorkManager выбран для устойчивого выполнения фоновой синхронизации.

### 1.4 Заимствования и авторская часть
1. Допустимы заимствования из официальной документации библиотек и SDK.
2. Допустимы типовые инфраструктурные шаблоны из официальных источников.
3. К авторской части относятся пользовательские потоки, прикладная логика и экранные сценарии CoTrip.
4. Не относится к авторской логике внутренний код внешних SDK и сгенерированные файлы сборки.

### 1.5 Внешние зависимости и ограничения
1. Push-уведомления зависят от разрешений устройства и доступности канала доставки.
2. Экран погоды зависит от доступности внешнего погодного провайдера.
3. Экран AI-подсказок зависит от доступности внешнего AI-провайдера.

### 1.6 Ссылки на исходный код клиентской части
1. Общий репозиторий: https://github.com/ilya-nvk/cotrip
2. Клиентский код: https://github.com/ilya-nvk/cotrip/tree/main/android/app/src/main/java/nvk/cotrip

## 2. Серверная часть
Серверная часть CoTrip реализована в каталоге `backend/src/main/kotlin/nvk/cotrip/backend`.

### 2.1 Структура серверной части
1. `routes` - HTTP API-маршруты (`auth`, `trips`, `members`, `invites`, `ideas`, `comments`, `itinerary`, `expenses`, `weather`, `ai`, `sync`, `notifications`).
2. `db` - доступ к данным и репозитории предметных сущностей.
3. `auth` - валидация токенов и управление сессиями.
4. `ws` - WebSocket-канал для обсуждений идей.
5. `integrations` - внешние интеграции (погода, AI).
6. `notifications` - серверная публикация push-событий.
7. `plugins` - конфигурация Ktor (сериализация, маршрутизация, обработка ошибок, безопасность).

### 2.2 Используемые библиотеки и назначение
1. Kotlin - основной язык серверной реализации.
2. Ktor - HTTP/WebSocket сервер и middleware-цепочка.
3. PostgreSQL JDBC - доступ к PostgreSQL.
4. Kotlinx Serialization - сериализация JSON.
5. Firebase Admin SDK - отправка push-сообщений.

### 2.3 Обоснование выбора инструментов
1. Ktor выбран для реализации REST и WebSocket в одном технологическом стеке.
2. PostgreSQL выбран как транзакционное реляционное хранилище данных.
3. Kotlin выбран для унификации технологического стека клиента и сервера.

### 2.4 Заимствования и авторская часть
1. Допустимы заимствования инфраструктурных конфигураций из официальной документации Ktor/PostgreSQL.
2. К авторской части относятся маршруты предметной области, серверные правила валидации и синхронизация клиентских сценариев.
3. Не относится к авторской логике внутренний код внешних библиотек и SDK.

### 2.5 Внешние зависимости и ограничения
1. Серверные интеграции с погодой и AI зависят от доступности внешних API.
2. Отправка push-событий зависит от доступности Firebase Cloud Messaging.
