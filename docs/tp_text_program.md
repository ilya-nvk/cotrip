# ТЕКСТ ПРОГРАММЫ

## 1. Назначение документа
Документ фиксирует структуру программного кода CoTrip, состав компонентов, используемые библиотеки и источники заимствований.

---

## 2. Состав и структура программы

### 2.1 Клиентская часть (Android)
Корневой путь: `android/app/src/main/java/nvk/cotrip`.

Ключевые компоненты:
1. `ui` — экраны и пользовательские сценарии (авторизация, поездки, идеи, маршрут, расходы, настройки, погода, AI-подсказки).
2. `data/repository` — прикладная логика сценариев и координация источников данных.
3. `data/network` — API-клиенты, перехватчики, сетевые модели.
4. `data/cache` — локальные кэш-хранилища клиентских сущностей.
5. `data/sync` — офлайн-очередь и синхронизация после восстановления сети.
6. `notifications` — обработка push-уведомлений и переходов по событиям.
7. `di` — конфигурация внедрения зависимостей.

### 2.2 Серверная часть (Backend)
Корневой путь: `backend/src/main/kotlin/nvk/cotrip/backend`.

Ключевые компоненты:
1. `routes` — HTTP API-маршруты (`auth`, `trips`, `ideas`, `itinerary`, `expenses`, `sync`, `notifications`).
2. `db` — доступ к данным и репозитории доменных сущностей.
3. `auth` — валидация токенов и управление сессиями.
4. `ws` — WebSocket-канал для обсуждений идей.
5. `integrations` — внешние интеграции (погода, AI).
6. `notifications` — серверная публикация push-событий.
7. `plugins` — конфигурация Ktor (сериализация, маршрутизация, обработка ошибок, безопасность).

---

## 3. Используемые библиотеки и назначение

### 3.1 Клиент (Android)
1. **Kotlin** — основной язык клиентской реализации.
2. **Jetpack Compose** — декларативный UI клиентских экранов.
3. **AndroidX Navigation** — навигация между экранами.
4. **Hilt / Dagger** — внедрение зависимостей.
5. **Retrofit + OkHttp + Kotlinx Serialization** — HTTP-клиент и сериализация API-контрактов.
6. **Room** — локальная БД на клиенте.
7. **WorkManager** — фоновые задания синхронизации.
8. **Firebase Cloud Messaging SDK** — доставка push-уведомлений на устройство.

### 3.2 Сервер
1. **Kotlin** — основной язык серверной реализации.
2. **Ktor** — HTTP/WebSocket сервер и middleware-цепочка.
3. **PostgreSQL JDBC** — доступ к PostgreSQL.
4. **Kotlinx Serialization** — сериализация JSON.
5. **Firebase Admin SDK** — отправка push-сообщений.

---

## 4. Обоснование выбора инструментов
1. Kotlin используется на клиенте и сервере для унификации языка и снижения стоимости сопровождения.
2. Compose выбран для быстрой сборки UI и предсказуемого управления состоянием экранов.
3. Ktor выбран как серверный фреймворк с поддержкой REST и WebSocket в одном стеке.
4. PostgreSQL выбран как транзакционное хранилище с поддержкой реляционных связей доменной модели.
5. WorkManager выбран для устойчивого фонового выполнения синхронизации на Android.

## 5. Заимствования и источники

### 5.1 Допустимые заимствования
В проекте допускаются:
1. использование публичной документации библиотек и SDK;
2. использование типовых паттернов и шаблонов конфигурации из официальных источников;
3. использование open-source зависимостей по лицензиям, совместимым с учебным проектом.

### 5.2 Что является авторским
К авторской части проекта относятся:
1. прикладная доменная логика CoTrip;
2. сценарии экранов и пользовательские потоки;
3. серверные маршруты и правила валидации предметной области;
4. структура офлайн-синхронизации и связка клиентских/серверных сценариев.

### 5.3 Что не считается авторской логикой
1. сгенерированные файлы сборки и DI-каркас;
2. инфраструктурные шаблоны, повторяющие официальные примеры библиотек;
3. внешние SDK и их внутренние реализации.

---

## 6. Внешние зависимости и ограничения
1. Погодные сценарии зависят от доступности внешнего погодного провайдера.
2. AI-подсказки зависят от доступности AI-провайдера.
3. Push-уведомления зависят от разрешений устройства и доступности канала доставки.
