# Mermaid-схемы для ВКР (раздел 2)

## Что добавить в ВКР
1. Обязательно: схема 2.1 (пользовательский поток идея -> обсуждение -> маршрут).
2. Обязательно: схема 2.2 (обзорная архитектура системы).
3. Обязательно: схема 2.3 (офлайн-режим и синхронизация).
4. Дополнительно к 2.2 (рекомендуется): отдельная схема архитектуры клиента.
5. Дополнительно к 2.2 (рекомендуется): отдельная схема архитектуры бэкенда.

## Схема 2.1. Пользовательский поток
```mermaid
flowchart LR
  A["Создание идеи"] --> B["Обсуждение идеи в комментариях"]
  B --> C{"Решение по идее"}
  C -- "Одобрена" --> D["Добавление в маршрут дня"]
  C -- "Отклонена" --> E["Остается в списке идей"]
  D --> F["Упорядочивание активностей"]
```

## Схема 2.2. Обзорная архитектура системы
```mermaid
flowchart LR
  subgraph CL["Android-клиент"]
    UI["Экраны и навигация"]
    VM["ViewModel"]
    REP["Repository"]
    DB["Локальное хранилище"]
    Q["Офлайн-очередь"]
    UI --> VM --> REP
    REP --> DB
    REP --> Q
  end

  subgraph BE["Backend (Ktor)"]
    API["REST API / WebSocket"]
    SVC["Сервисы предметной области"]
    AUTH["Аутентификация и роли"]
    API --> SVC
    API --> AUTH
  end

  PG["PostgreSQL"]
  W["Погодный API"]
  AI["AI-провайдер"]
  PUSH["Провайдер уведомлений"]

  REP -->|"HTTP / WS"| API
  SVC --> PG
  SVC --> W
  SVC --> AI
  SVC --> PUSH
```

## Схема 2.2a. Архитектура клиента (рекомендуемая дополнительная)
```mermaid
flowchart TD
  N["Навигация приложения"] --> S["Экраны"]
  S --> V["ViewModel"]
  V --> R["Repository"]

  R --> L["Локальные источники данных"]
  R --> REM["Удаленные источники данных"]
  R --> SYNC["Очередь синхронизации"]

  L --> ROOM["Локальная БД / кэш"]
  REM --> API["REST / WebSocket API"]
  SYNC --> WORKER["Фоновая отправка после восстановления сети"]
  WORKER --> API
```

## Схема 2.2b. Архитектура бэкенда (рекомендуемая дополнительная)
```mermaid
flowchart TD
  IN["Входящий запрос"] --> ROUTES["Маршруты API"]
  ROUTES --> AUTH["Проверка аутентификации и прав"]
  AUTH --> SERVICES["Сервисы: поездки, идеи, маршрут, расходы, приглашения"]

  SERVICES --> REPO["Слой доступа к данным"]
  REPO --> PG["PostgreSQL"]

  SERVICES --> WS["Публикация событий (WebSocket)"]
  SERVICES --> EXTW["Интеграция погоды"]
  SERVICES --> EXTAI["Интеграция AI"]
  SERVICES --> NOTIF["Отправка уведомлений"]
```

## Схема 2.3. Офлайн-режим и синхронизация
```mermaid
flowchart LR
  A["Сеть недоступна"] --> B["Пользователь выполняет действие"]
  B --> C["Действие сохраняется локально"]
  C --> D["Запись в офлайн-очередь"]
  D --> E["Сеть восстановлена"]
  E --> F["Очередь отправляется на сервер"]
  F --> G["Сервер применяет изменения"]
  G --> H["Клиент обновляет состояние экранов"]
```
