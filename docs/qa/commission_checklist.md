# Чек-лист комиссии КТ3/ВКР (программная работа)

Источник: `/Users/ilya-nvk/Downloads/Защиты KТ3 - ВКР ПИ 25_26 (студ) - состав комиссий.csv`.

## 1. Обязательный комплект
1. Текст ВКР с введением, главами 1-3, выводами по главам, заключением и приложениями.
2. Утвержденное ТЗ.
3. ПМИ.
4. ТП.

## 2. Что комиссия проверяет в первую очередь
1. Рабочий проект с функционалом по ТЗ.
2. Испытания, подтверждающие ТЗ по ПМИ.
3. Отсутствие противоречий между ТЗ, ПМИ, ВКР и кодом.
4. В презентации: цели/задачи, анализ аналогов, выбор технологий и обоснование, реализация по ТЗ, результаты и выводы.
5. Готовность ответить на вопросы комиссии по реализации и документации за 7-10 минут защиты.

## 3. Definition of Done по документам

### 3.1 ТЗ
1. Все требования проверяемые и однозначные.
2. Термины взяты из глоссария ТЗ.
3. Есть правило локализации UI (`ru` -> русский, иначе английский).
4. Правила удаления комментариев заданы явно (автор/не автор).

### 3.2 ПМИ
1. Проверяются только клиентские сценарии.
2. Нет обязательных серверных/CI/покрытийных метрик.
3. Для каждого placeholder есть инструкция, какой скриншот нужен.
4. Матрица трассируемости ТЗ -> сценарии ПМИ заполнена.

### 3.3 ВКР
1. Описание реализации соответствует коду.
2. Нет утверждений, противоречащих фактическому поведению.
3. Выбор инструментов обоснован критериями и альтернативами.
4. Метрики Android+backend обозначены как инженерный контроль разработки, а не как замена клиентского ПМИ.

### 3.4 ТП
1. Описаны структура, компоненты, библиотеки.
2. Указаны заимствования и границы авторской части.
3. Указаны внешние зависимости и эксплуатационные ограничения.

## 4. Предзащитный быстрый контроль (10 минут)
1. Открыть `docs/tz.md`, `docs/pmi.md`, `docs/vkr/vkr_full.md`, `docs/tp_text_program.md`.
2. Проверить, что одинаковые термины трактуются одинаково.
3. Проверить, что все placeholders содержат понятную инструкцию по вставке.
4. Пройти 3 демонстрационных сценария: идеи/комментарии, маршрут, расходы.
5. Проверить локализацию на `ru` и `en`.
