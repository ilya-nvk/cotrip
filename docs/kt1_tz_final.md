# Андроид-приложение для совместного планирования поездок
## Техническое задание (финализированная редакция)

Обозначение документа: `RU.17701729.05.05-01 ТЗ`  
Дата редакции: `18.03.2026`

---

## Аннотация
ТЗ фиксирует проверяемые требования к пользовательскому поведению Android-приложения CoTrip.
Требования сформулированы так, чтобы их можно было проверить по шагам в ПМИ без интерпретаций.

---

## Глоссарий
- **Приложение (CoTrip)**: мобильное Android-приложение для совместного планирования поездок.
- **Пользователь**: авторизованный человек, выполняющий действия в приложении.
- **Поездка**: сущность с датами, участниками, идеями, маршрутом и расходами.
- **Владелец поездки**: пользователь, создавший поездку.
- **Участник поездки**: пользователь, присоединившийся к поездке.
- **Идея**: предложение активности или места до включения в маршрут.
- **Комментарий идеи**: сообщение в обсуждении конкретной идеи.
- **Активность**: элемент маршрута на конкретный день.
- **Расход**: запись о сумме, плательщике и распределении между участниками.
- **Баланс**: итоговое финансовое состояние пользователя в рамках поездки.
- **Дни вне диапазона**: дни маршрута, которые выходят за текущий диапазон дат поездки.
- **Подсказка ИИ**: предложение активности, сгенерированное модулем ИИ.
- **Офлайн-очередь**: локально сохраненные изменения, отправляемые после восстановления сети.
- **Глубокая ссылка**: ссылка, открывающая конкретный экран приложения.

В тексте ТЗ используются только термины из этого глоссария.

## 1 Введение

### 1.1 Наименование программы
- Наименование на русском: **Андроид-приложение для совместного планирования поездок**.
- Наименование на английском: **Android Application for Collaborative Trip Planning**.
- Краткое имя: **CoTrip**.

### 1.2 Область применения
Приложение предназначено для групп пользователей, планирующих поездку: идеи, обсуждение, маршрут, расходы, погода и подсказки ИИ в одном интерфейсе.

## 2 Основания для разработки
- Учебный проект направления 09.03.04 «Программная инженерия».
- Репозиторий проекта CoTrip как источник фактической реализации.

---

## 3 Назначение разработки

### 3.1 Функциональное назначение
Приложение должно поддерживать пользовательские сценарии:
1. вход и управление профилем;
2. создание и ведение поездок;
3. приглашение и присоединение участников;
4. работа с идеями и обсуждениями;
5. построение маршрута по дням;
6. учет расходов и просмотр баланса;
7. просмотр погоды;
8. генерация и сохранение подсказок ИИ;
9. работу при кратковременной потере сети.

### 3.2 Эксплуатационное назначение
Приложение используется на Android-смартфонах пользователями без специальной технической подготовки.

## 4 Требования к программе

### 4.1 Функциональные требования

#### 4.1.1 Авторизация и профиль
**Предусловия**: устройство подключено к сети, пользователь не авторизован.  
**Действия**: вход через Google, изменение имени/фото, выход, удаление профиля.  
**Ожидаемый результат**:
1. после входа открывается экран списка поездок;
2. измененные имя и фото отображаются после повторного открытия настроек;
3. после выхода пользователь видит экран входа;
4. после удаления профиля пользователь возвращается на экран входа.
**Ограничения**:
1. пустое имя профиля не сохраняется;
2. при сетевой ошибке отображается сообщение об ошибке.

#### 4.1.2 Поездки
**Предусловия**: пользователь авторизован.  
**Действия**: создание, редактирование, удаление, просмотр деталей поездки.  
**Ожидаемый результат**:
1. поездка создается при заполнении обязательных полей;
2. поездка отображается в списке пользователя;
3. изменения поездки отображаются после повторного открытия;
4. удаленная поездка не отображается в списке.
**Ограничения**:
1. название поездки обязательно;
2. дата окончания не может быть раньше даты начала;
3. дата начала не может быть раньше текущей даты.

#### 4.1.3 Приглашения и присоединение
**Предусловия**: поездка создана владельцем.  
**Действия**: генерация ссылки-приглашения, присоединение второго пользователя.  
**Ожидаемый результат**:
1. ссылка-приглашение создается и копируется;
2. валидная ссылка приводит к присоединению пользователя;
3. после присоединения пользователь видит поездку и состав участников.
**Ограничения**:
1. невалидная или просроченная ссылка не приводит к присоединению;
2. повторное присоединение не создает дубликат участника.

#### 4.1.4 Идеи и обсуждения
**Предусловия**: пользователь является участником поездки.  
**Действия**: создание/редактирование/удаление идеи, отправка комментариев, смена статуса идеи, перенос идеи в маршрут.  
**Ожидаемый результат**:
1. идея отображается в списке идей поездки;
2. комментарий, отправленный пользователем А, отображается у пользователя Б без ручного обновления;
3. статус идеи принимает одно из значений: `ожидает`, `одобрена`, `отклонена`;
4. идею можно добавить в выбранный день маршрута.
**Ограничения**:
1. заголовок идеи обязателен;
2. пустой комментарий не отправляется;
3. удаление комментария разрешено только автору этого комментария;
4. попытка удалить чужой комментарий завершается отказом операции.

#### 4.1.5 Маршрут
**Предусловия**: поездка существует.  
**Действия**: выбор города дня, создание/редактирование/удаление активности, изменение порядка, перенос между днями.  
**Ожидаемый результат**:
1. маршрут отображается по дням поездки;
2. активность добавляется только при непустом названии;
3. измененный порядок активностей сохраняется после повторного открытия экрана;
4. при изменении дат поездки пользователь выбирает обработку дней вне диапазона.

#### 4.1.6 Расходы и баланс
**Предусловия**: в поездке есть минимум два участника.  
**Действия**: создание расхода, выбор участников, выбор плательщика, изменение статуса оплаты.  
**Ожидаемый результат**:
1. расход отображается в списке расходов поездки;
2. по поездке отображаются суммы `оплачено`, `запланировано` и баланс пользователя;
3. в деталях расхода отображаются доли участников и их статус оплаты.
**Ограничения**:
1. сумма и название расхода обязательны;
2. расход должен содержать хотя бы одного участника.

#### 4.1.7 Погода
**Предусловия**: в маршруте выбран город.  
**Действия**: открытие экрана прогноза, обновление прогноза.  
**Ожидаемый результат**:
1. прогноз отображается для выбранного города;
2. на экране явно отображается покрытие дат;
3. при отсутствии данных отображается сообщение о недоступности.

#### 4.1.8 Подсказки ИИ
**Предусловия**: выбран город.  
**Действия**: генерация подсказок, сохранение одной подсказки в идеи.  
**Ожидаемый результат**:
1. отображается список подсказок;
2. сохраненная подсказка появляется в списке идей поездки;
3. сохраненная подсказка помечена как сохраненная.

#### 4.1.9 Настройки уведомлений
**Предусловия**: пользователь авторизован.  
**Действия**: изменение переключателей категорий уведомлений, повторное открытие экрана, открытие приложения из push-уведомления.  
**Ожидаемый результат**:
1. состояния переключателей сохраняются;
2. открытие push-уведомления переводит пользователя в связанный сценарий приложения.

#### 4.1.10 Офлайн-поведение
**Предусловия**: часть данных поездки ранее загружена на устройство.  
**Действия**: отключение сети, выполнение доступных действий, восстановление сети.  
**Ожидаемый результат**:
1. ранее загруженные данные доступны без сети;
2. действия пользователя сохраняются в офлайн-очередь;
3. после восстановления сети офлайн-очередь отправляется и экраны обновляются.

#### 4.1.11 Локализация интерфейса
**Правило языка**:
1. если язык системы `ru`, интерфейс приложения отображается на русском;
2. во всех остальных системных языках интерфейс отображается на английском.
**Правило форматирования даты/времени**:
1. для `ru` используются русские названия месяцев/дней недели;
2. для не-`ru` используется английское форматирование.

#### 4.1.12 Границы версии
В версию не входят:
1. отображение маршрута на карте;
2. единый глобальный поиск по всем сущностям;
3. пользовательские сценарии, доступные только через прямой вызов API без экранов приложения.

### 4.2 Временные характеристики
1. в операциях ожидания отображается индикатор загрузки;
2. пользователь получает визуальную обратную связь до получения ответа сервера.

### 4.3 Надежность
1. сетевые и серверные ошибки отображаются сообщением в интерфейсе;
2. невалидный ввод не приводит к аварийному завершению;
3. после перезапуска приложения доступ к данным пользователя сохраняется в рамках активной сессии или кэша.

### 4.4 Условия эксплуатации
1. целевая платформа: Android `8.0+` (API 26+);
2. для онлайн-сценариев требуется доступ в интернет.

## 7 Порядок контроля и приемки

### 7.1 Общие условия приемки
Работа принимается при одновременном выполнении условий:
1. реализованы пользовательские требования раздела 4.1;
2. ПМИ подтверждает выполнение сценариев;
3. между ТЗ, ПМИ, ВКР и кодом нет противоречий.

### 7.2 Приемочные сценарии
1. Авторизация: вход через Google, открытие списка поездок.
2. Профиль: изменение имени, сохранение после повторного открытия.
3. Поездка: создание поездки с валидными датами.
4. Приглашение: присоединение второго пользователя по ссылке.
5. Идеи: новый комментарий виден второму участнику без ручного обновления.
6. Маршрут: порядок активностей сохраняется после повторного открытия.
7. Дни вне диапазона: выбор действия и применение результата.
8. Расходы: пересчет итогов и баланса после создания расхода.
9. Погода: отображение прогноза и покрытия дат.
10. Подсказки ИИ: сохранение подсказки в идеи.
11. Уведомления: сохранение настроек категорий и переход по push.
12. Офлайн: запись действий без сети и синхронизация после восстановления.
13. Локализация: русский UI при `ru`, английский UI при не-`ru`.
