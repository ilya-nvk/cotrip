\section*{АННОТАЦИЯ}
\addcontentsline{toc}{section}{АННОТАЦИЯ}
Программа и методика испытаний является документом, который устанавливает порядок приемочных испытаний Android-приложения для совместного планирования поездок.
Документ содержит описание объекта испытаний, целей испытаний, проверяемых требований, используемых средств, порядка выполнения испытаний и методов проверки пользовательских сценариев.

Настоящий документ разработан в соответствии с требованиями:
\begin{enumerate}
  \item ГОСТ 19.101-77: Виды программ и программных документов;
  \item ГОСТ 19.102-77: Стадии разработки;
  \item ГОСТ 19.103-77: Обозначения программ и программных документов;
  \item ГОСТ 19.104-78: Основные надписи;
  \item ГОСТ 19.105-78: Общие требования к программным документам;
  \item ГОСТ 19.106-78: Требования к программным документам, выполненным печатным способом;
  \item ГОСТ 19.301-79: Программа и методика испытаний. Требования к содержанию и оформлению;
  \item ГОСТ 19.603-78: Общие правила внесения изменений;
  \item ГОСТ 19.604-78: Правила внесения изменений в программные документы, выполненные печатным способом.
\end{enumerate}

\section*{1. ОБЪЕКТ ИСПЫТАНИЙ}
\addcontentsline{toc}{section}{1. ОБЪЕКТ ИСПЫТАНИЙ}

\subsection*{1.1 Наименование программы}
Наименование программы: «Андроид-приложение для совместного планирования поездок».\\
Краткое наименование программы: «CoTrip».

\subsection*{1.2 Краткая характеристика области применения}
Объект испытаний --- Android-клиент CoTrip для совместного планирования поездок.
В рамках настоящего документа проверяются пользовательские сценарии, выполняемые через интерфейс мобильного приложения.

\clearpage
\section*{2. ЦЕЛЬ ИСПЫТАНИЙ}
\addcontentsline{toc}{section}{2. ЦЕЛЬ ИСПЫТАНИЙ}
Цель испытаний --- подтвердить соответствие пользовательских сценариев приложения требованиям раздела 4 документа «Техническое задание».
Испытания считаются успешными, если сценарии выполняются без критических отклонений, результаты соответствуют ожидаемым, а интерфейс соблюдает установленное правило локализации.

\clearpage
\section*{3. ТРЕБОВАНИЯ К ПРОГРАММЕ}
\addcontentsline{toc}{section}{3. ТРЕБОВАНИЯ К ПРОГРАММЕ}

\subsection*{3.1 Функциональные требования}
На испытания выносятся требования ТЗ 4.1.1---4.1.9 и 4.1.11:
\begin{enumerate}
  \item авторизация и профиль;
  \item поездки;
  \item приглашения и присоединение;
  \item идеи и обсуждения;
  \item маршрут;
  \item расходы и баланс;
  \item погода;
  \item подсказки искусственного интеллекта;
  \item настройки уведомлений;
  \item локализация интерфейса.
\end{enumerate}

\subsection*{3.2 Нефункциональные требования}
На испытания выносятся требования ТЗ 4.2---4.4:
\begin{enumerate}
  \item отображение индикаторов загрузки в операциях ожидания;
  \item отображение сообщений об ошибках при сетевых и валидационных сбоях;
  \item продолжение работы после перезапуска приложения;
  \item соответствие целевой платформе Android 8.0+ и условиям онлайн-доступа.
\end{enumerate}

\section*{5. СРЕДСТВА И ПОРЯДОК ИСПЫТАНИЙ}
\addcontentsline{toc}{section}{5. СРЕДСТВА И ПОРЯДОК ИСПЫТАНИЙ}

\subsection*{5.1 Технические средства}
\begin{enumerate}
  \item два Android-устройства с доступом в интернет;
  \item оба устройства должны работать на Android 8.0+ (API 26+);
  \item минимум два тестовых аккаунта для совместных сценариев.
\end{enumerate}

\subsection*{5.2 Программные средства}
\begin{enumerate}
  \item установленное приложение CoTrip актуальной сборки;
  \item возможность переключения системного языка устройства;
  \item средство фиксации результатов (скриншоты).
\end{enumerate}

\subsection*{5.3 Порядок проведения испытаний}
\begin{enumerate}
  \item выполнить предусловия сценария;
  \item выполнить действия сценария;
  \item зафиксировать ожидаемый результат.
\end{enumerate}

\subsection*{5.4 Требования к персоналу}
Испытания выполняет оператор, владеющий базовыми навыками работы с Android-устройством и учетной записью Google.

\subsection*{6.1 Авторизация через Google}
Необходимо проверить:
\begin{enumerate}
  \item вход через Google для неавторизованного пользователя;
  \item автоматический переход на экран списка поездок после успешного входа.

Ожидаемое состояние приложения: пользователь авторизован, открыт экран списка поездок с данными пользователя.
\screenshotplaceholder{Экран списка поездок после успешного входа через Google.}{../../assets/processed/12_1.png}

\subsection*{6.2 Профиль}
Необходимо проверить:
\begin{enumerate}
  \item изменение имени и фото профиля с сохранением после повторного открытия настроек;
  \item при пустом имени профиля кнопка сохранения неактивна;
  \item отображение сообщения при сетевой ошибке во время сохранения;
  \item выход из аккаунта с переходом на экран входа;
  \item удаление профиля с переходом на экран входа.
\end{enumerate}
Ожидаемое состояние приложения: валидные изменения профиля сохраняются, невалидные блокируются, выход и удаление возвращают пользователя на экран входа.
\screenshotplaceholder{Экран настроек профиля после сохранения изменений.}{../../assets/processed/13_1.png}

\subsection*{6.3 Поездка}
Необходимо проверить:
\begin{enumerate}
  \item создание, редактирование и удаление поездки владельцем;
  \item отображение новой поездки в списке после создания и отсутствие в списке после удаления;
  \item при пустом названии поездки кнопка сохранения неактивна;
  \item в календаре даты начала недоступны даты раньше текущей даты и даты позже чем через один год;
  \item в календаре даты окончания недоступны даты раньше даты начала и даты позже чем через шесть месяцев после даты начала;
  \item при наличии существующей поездки с исходной парой дат ее сохранение при редактировании других полей.
\end{enumerate}
Ожидаемое состояние приложения: поездка корректно создается, редактируется и удаляется; недопустимые даты недоступны для выбора; при наличии поездки со старой парой дат сохранение исходных дат при редактировании поддерживается.
\screenshotplaceholder{Форма поездки с недоступными датами вне допустимого диапазона.}{../../assets/processed/22_1.png}

\subsection*{6.4 Приглашение и присоединение}
Необходимо проверить:
\begin{enumerate}
  \item генерацию ссылки-приглашения владельцем поездки;
  \item присоединение второго пользователя по корректной ссылке;
  \item появление поездки у второго пользователя и обновление состава участников;
  \item отсутствие дубликата участника при повторном присоединении;
  \item отказ присоединения по ссылке некорректного формата.
\end{enumerate}
Ожидаемое состояние приложения: корректная ссылка добавляет участника в поездку, невалидная ссылка отклоняется, повторное присоединение не дублирует участника.
\screenshotplaceholder{Экран генерации ссылки-приглашения в поездку.}{../../assets/processed/24_1.png}

\subsection*{6.5 Идеи и обсуждения}
Необходимо проверить:
\begin{enumerate}
  \item создание, редактирование и удаление идеи;
  \item изменение статуса идеи (\texttt{ожидает}, \texttt{одобрена}, \texttt{отклонена});
  \item добавление идеи в выбранный день маршрута;
  \item отправку комментария и его отображение у второго участника без ручного обновления;
  \item при пустом заголовке идеи кнопка сохранения неактивна, при пустом комментарии кнопка отправки неактивна;
  \item отсутствие удаления комментариев в пользовательском интерфейсе текущей версии.
\end{enumerate}
Ожидаемое состояние приложения: идеи и комментарии обрабатываются по правилам, статусы и связь с маршрутом отображаются корректно, невалидный ввод блокируется.
\screenshotplaceholder{Экран идеи со статусом и обсуждением участников.}{../../assets/processed/30_1.png}
\textbf{Примечание:} удаление комментариев не входит в пользовательский контур текущей версии.

\subsection*{6.6 Маршрут и активности}
Необходимо проверить:
\begin{enumerate}
  \item выбор города для дня поездки;
  \item добавление, редактирование и удаление активности;
  \item перенос активности между днями;
  \item отображение маршрута по дням;
  \item сохранение переноса активности после повторного открытия экрана;
  \item при пустом названии активности кнопка сохранения неактивна.
\end{enumerate}
Ожидаемое состояние приложения: маршрут по дням отображается корректно, изменения сохраняются, невалидная активность не добавляется.
\screenshotplaceholder{Экран маршрута после переноса активности между днями.}{../../assets/processed/31_1.png}

\subsection*{6.7 Обработка дней вне диапазона}
Необходимо проверить:
\begin{enumerate}
  \item отображение экрана выбора способа обработки дней вне диапазона;
  \item сценарий «продлить окончание»;
  \item сценарий «удалить лишние дни».
\end{enumerate}
Ожидаемое состояние приложения: после выбора действия маршрут и даты поездки соответствуют выбранному варианту обработки.
\screenshotplaceholder{Экран результата после обработки дней вне диапазона дат.}{../../assets/processed/32_1.png}

\subsection*{6.8 Расходы и баланс}
Необходимо проверить:
\begin{enumerate}
  \item создание расхода с выбором плательщика и участников;
  \item отображение расхода в списке, отображение сумм «оплачено», «запланировано» и баланса;
  \item отображение долей участников и статусов оплаты в карточке расхода;
  \item изменение статуса оплаты с сохранением результата;
  \item при незаполненных обязательных полях расхода кнопка сохранения неактивна.
\end{enumerate}
Ожидаемое состояние приложения: расходы и баланс отображаются корректно, статусы оплаты сохраняются, невалидный расход не сохраняется.
\screenshotplaceholder{Экран расходов с балансом и статусами оплаты участников.}{../../assets/processed/33_1.png}

\subsection*{6.9 Погода}
Необходимо проверить:
\begin{enumerate}
  \item открытие экрана прогноза и обновление прогноза;
  \item отображение прогноза для выбранного города и покрытия дат;
  \item отображение поясняющего сообщения при отсутствии города или недоступности прогноза.
\end{enumerate}
Ожидаемое состояние приложения: пользователь видит либо актуальный прогноз с покрытием дат, либо понятную причину отсутствия данных.
\screenshotplaceholder{Экран прогноза погоды в контексте поездки.}{../../assets/processed/34_1.png}

\subsection*{6.10 Подсказки искусственного интеллекта}
Необходимо проверить:
\begin{enumerate}
  \item генерацию списка подсказок для выбранного города;
  \item сохранение выбранной подсказки в идеи;
  \item отображение сохраненной подсказки в списке идей и в списке подсказок как сохраненной.
\end{enumerate}
Ожидаемое состояние приложения: подсказки генерируются и сохраняются в идеи с корректной визуальной отметкой.
\screenshotplaceholder{Экран подсказок ИИ с сохраненной рекомендацией.}{../../assets/processed/35_1.png}

\subsection*{6.11 Настройки уведомлений}
Необходимо проверить:
\begin{enumerate}
  \item включение/выключение категорий уведомлений и сохранение состояний после повторного открытия экрана;
  \item переход в связанный раздел приложения при открытии уведомления (при выданном системном разрешении и доступной доставке);
  \item поддерживаемые типы событий: новый комментарий к идее, новая идея, новый расход, изменение статуса оплаты расхода.
\end{enumerate}
Ожидаемое состояние приложения: настройки уведомлений сохраняются, уведомления открывают соответствующие экраны.
\screenshotplaceholder{Экран настроек уведомлений с сохраненными параметрами.}{../../assets/processed/36_1.png}

\subsection*{6.12 Локализация интерфейса}
Необходимо проверить:
\begin{enumerate}
  \item отображение интерфейса на русском языке при русском языке системы;
  \item отображение интерфейса на английском языке при любом другом языке системы.
\end{enumerate}
Ожидаемое состояние приложения: язык интерфейса соответствует языку системы по правилам ТЗ.
\screenshotplaceholder{Экран локализованного интерфейса приложения.}{../../assets/processed/37_1.png}

\subsection*{6.13 Надежность: ошибки сети и валидация}
Необходимо проверить:
\begin{enumerate}
  \item при невалидном вводе отправка формы не выполняется (кнопка действия неактивна);
  \item отображение сообщений о сетевой или серверной ошибке;
  \item отсутствие аварийного завершения приложения в обоих случаях.
\end{enumerate}
Ожидаемое состояние приложения: ошибки корректно отображаются пользователю, приложение остается работоспособным.
\screenshotplaceholder{Экран обработки ошибки сети или невалидного ввода.}{../../assets/processed/38_1.png}

\subsection*{6.14 Продолжение работы после перезапуска}
Необходимо проверить:
\begin{enumerate}
  \item запуск приложения после полного закрытия без ошибок;
  \item продолжение работы с данными пользователя после перезапуска (активная сессия или кэш).
\end{enumerate}
Ожидаемое состояние приложения: после перезапуска пользователь может продолжить работу с актуальными данными.
\screenshotplaceholder{Экран приложения после перезапуска с сохраненными данными.}{../../assets/processed/39_1.png}

\subsection*{6.15 Временные характеристики: индикаторы загрузки}
Необходимо проверить:
\begin{enumerate}
  \item отображение индикатора загрузки в операциях ожидания ответа;
  \item наличие визуальной обратной связи пользователю до получения ответа сервера;
  \item скрытие индикатора после завершения операции и отображение результата.
\end{enumerate}
Ожидаемое состояние приложения: пользователь всегда видит состояние выполнения долгой операции, после завершения отображается итоговый результат.
